# ScanFlow 0.3.0 · сборка 13

Полный накопительный проект с прежним Bundle ID ua.autosplit.scanner и базой ScanFlow-v2. Установка поверх приложения сохраняет сканы.

## Новое в 0.3.0

- В активной камере отключена автоблокировка; прежнее состояние восстанавливается при выходе и уходе в фон.
- Анализ видеокадров ограничен 1100 пикселями, интервал снижен с 450 до 200 мс. Это настройки частоты, а не замер FPS устройства.
- Поиск рассматривает несколько прямоугольников и периодически использует системное выделение документа. Снижены слишком жёсткие пороги размера/уверенности. Проверка фотографии отдельно сохраняет защиту содержимого от обрезки.
- Устойчивость копится по времени с допуском дрожи; яркость сравнивается после вычитания среднего. Подстройка экспозиции не сбрасывает таймер, автофокус ожидается ограниченное время. Краткая потеря углов сохраняет контур, а смена страницы требует устойчивого изменения.
- Лупа 3× со смещением от пальца показывает точное положение угла. Перетягивание сохраняет начальное смещение касания: точка не прыгает в центр пальца.
- «Білий кольоровий»: локальный системный CIDocumentEnhancer, amount 4, по примеру документации Apple. Он корректирует фон/тени и контраст без перевода в чёрно-белый режим. Реальное качество и сохранность мелких деталей требуют проверки на устройстве.
- Новые фото получают белый цветной стиль, импорт PDF по умолчанию остаётся исходным. Предпросмотр камеры и финальная обработка используют один стиль.
- Пакетное применение стиля: обработка по одной странице из оригиналов в фоне, сохранение после страницы, остановка между страницами. Ручные углы, повороты, кисть и порядок сохраняются. После полного применения стиль наследуется новыми страницами этого документа. При частичной остановке явно показано число обновлённых страниц.
- Фото-вспышка по-прежнему запрашивается через AVCapturePhotoSettings.flashMode = .on с качеством .quality. Факт срабатывания проверяется по результату снимка. Произвольное управление мощностью фотоимпульса публичным API не предоставляется; тени не являются измерением его мощности.

## Проверки и ограничения

Проверены комплектность, совместимый идентификатор приложения и синтаксический разбор всех Swift-файлов. В tests/main.swift добавлены сценарии дрожи, изменения яркости, пропуска контура, длительного автофокуса, сильного движения и защиты от повторной съёмки. Эти Swift-тесты выполняются в GitHub Actions, здесь Swift/Xcode отсутствуют. Синтаксический разбор не заменяет компиляцию и проверку камеры на iPhone.

Предыдущий отчёт validation/reference_check.json относится ТОЛЬКО к модели обработки краёв 0.2.10; он не подтверждает новый системный фильтр или качество камеры. Обработка краёв 0.2.10 сохранена без изменения. Старые страницы автоматически не переводятся в новый стиль: это отдельное явное действие.

Инструкция установки и проверки: READ_ME_FIRST_RU.md.

# ScanFlow 0.2.10 · сборка 12

Полный исходный проект. Bundle ID ua.autosplit.scanner и база приложения сохранены. Обновление устанавливается поверх текущего приложения; удалять его не нужно.

## Исправление по исходному PDF из 16 страниц

Проверялись страницы 2 и 11. Вертикальная фактура уже присутствует на исходном скане; это не новый фон, который можно безопасно полностью стереть без анализа содержимого.

1. В подбор образцов бумаги больше не допускаются тёмные пиксели текста и фотографий. Для фона используются светлые нейтральные образцы, из каждого участка выбирается светлая треть. Размер сетки уменьшен: она моделирует освещение, а не повторяет контуры букв. Это устраняет источник искусственных серых пятен при заполнении.
2. Смешивание очистки никогда не уменьшает значения исходных RGB-каналов. Светлый исходный пиксель не может стать серее из-за тёмного образца бумаги. Это правило относится к растровой обработке до последующего JPEG-кодирования, которое само по себе может немного менять пиксели.
3. Слабая синева JPEG больше не считается достаточным признаком синих чернил. Настоящие синие и красные отметки защищаются в основной маске и плавном переходе.
4. Тёмные штрихи рядом с подтверждённой деревянной фактурой включаются в очистку. Чёрный текст на нейтральной бумаге по-прежнему защищён.
5. Сохранены выборочный запуск обработки, запас очистки 0–24 px и ширина плавного перехода. Для контрольного результата использованы 19 px и 12%, как на присланном скриншоте. Для новых сканов по умолчанию остаются 8 px и 6%.
6. Существующие страницы пересчитываются из сохранённых оригиналов при открытии документа. Повторный импорт исходного PDF полезен для сравнения, если ранее вручную изменялись углы или применялась кисть. Полное восстановление сбрасывает ручные правки, без необходимости его не запускайте.

## Проверка на настоящих страницах

В отдельной Python-модели растрового этапа, соответствующей новой логике, обработаны исходные изображения страниц 2 и 11 без скриншотного интерфейса. Проверены:
- отсутствие затемнения исходных RGB-каналов на всей площади обеих страниц;
- отсутствие изменений тёмного текста в проверенной области страницы 2;
- полное совпадение пикселей в выбранных прямоугольниках двух портретов и подписи на странице 11;
- неизменность пикселей вне маски и её плавного перехода.

Координаты проверенных областей: страница 11 — верхний портрет x1120..1405, y340..730; нижний x1135..1420, y1535..1890; подпись x1210..1450, y2120..2260. Страница 2 — пиксели с максимальным RGB <120 в области x190..1600, y650..2320. Координаты исходных встроенных изображений, верхний левый угол — начало отсчёта.

Контрольный PDF содержит только эти две страницы и показывает результат модели. Он намеренно сохранён без потерь для сравнения, поэтому крупнее сжатого экспорта. Это не PDF, экспортированный нативной сборкой iPhone.

В tests/main.swift добавлены проверки отсутствия серого ореола, сохранения светлой бумаги, удаления тёмного зерна стола и защиты слабых синих штрихов. Локально проверены структура пакета и синтаксис Swift-файлов. В данной среде нет Swift/Xcode/iPhone: нативные тесты, сборка и производительность подтверждаются новым запуском GitHub Actions и проверкой на устройстве. Модель не заменяет нативный тест.

## Ограничения

Очистка работает с наружной каймой после определения границ, а не с любым содержимым листа. Текстуру ксерокопии, тени самого оригинала, фото, печати и рукопись нельзя автоматически считать мусором. Никаких обещаний идеальной сегментации нет. Сверьте границы, печати, подписи и мелкий текст перед использованием.

## Дополнение 0.2.10: остаточные коричневые точки

Уточнён фильтр красных чернил: слабонасыщенные красно-коричневые фрагменты стола больше не защищаются как насыщенная красная печать. Настоящие насыщенные красные/синие отметки остаются защищены; бледная красная печать на нейтральной бумаге защищается также по локальному контрасту и цветности.

Сравнение на тех же встроенных исходных изображениях страниц 2 и 11, с параметрами 19 px / 12%: в последних 30 строках каждой страницы число тёмных тёплых пикселей снизилось с 8 до 0. Точный критерий измерения: R-B>15, G-B>-5, R<235. Это проверка наружных коричневых остатков в контрольной модели; она не означает, что из документа удаляются все мелкие точки и фактура.

Повторно проверены незатемнение исходных RGB-каналов, неизменность двух портретов и подписи в отмеченных областях страницы 11, тёмного текста в отмеченной области страницы 2 и пикселей вне альфа-маски. Новые регрессионные тесты проверяют реальные цвета видимых остаточных точек, насыщенные красные отметки и бледную красную печать. Нативный Swift-код здесь не запускался; это требует GitHub Actions.

Новый контрольный PDF сохранён без потерь, содержит только исходные страницы 2 и 11 после обработки моделью 0.2.10. Нативная сборка iPhone в этой среде недоступна.
